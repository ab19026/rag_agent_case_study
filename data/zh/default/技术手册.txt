 上篇：系统操作手册

 一、系统概述与登录
ACIP是安诚人寿自主研发的一站式保险核心业务平台，整合了投保、核保、缴费、保单服务、理赔、双录质检、反洗钱、佣金计算及数据报表等全流程功能。系统采用B/S架构，支持Chrome、Edge最新版浏览器。

访问地址：  
- 生产环境：`https://acip.encheng-life.com`
- UAT测试环境：`https://uat-acip.encheng-life.com`（内勤验证用）

登录方式：
- 内勤及管理人员使用公司域账号+密码+短信OTP双因子认证。
- 外勤代理人登录代理人专属门户`agent.encheng-life.com`,通过企业微信扫码或手机号+验证码登录，仅开放投保、佣金查看、双录上传等受限模块。

角色权限矩阵（节选）：
| 角色 | 可访问模块 |
|------|------------|
| 保险顾问(代理人) | 客户新建、计划书、在线投保、双录上传、佣金明细、我的客户 |
| 契约岗/内勤 | 投保单初审、双录质检、问题件下发、回执追踪 |
| 核保师 | 人工核保交互、病史问卷下发、体检函生成、核保结论录入 |
| 理赔岗 | 报案登记、理赔资料审核、调查跟进、理算、结案 |
| 合规/法务 | 反洗钱审核、可疑交易甄别、双录抽检、投诉处理流转 |
| 系统管理员 | 用户权限分配、机构树维护、码表配置、工作日历设定 |

 二、新契约与投保管理
此模块对应员工手册第九章、第十章销售合规与核保承保要求。

1. 客户信息新建与校验  
   - 录入客户姓名、证件类型、证件号、手机号。系统自动校验实名认证（对接公安一所实名认证接口）。  
   - 若证件号为外国人永久居留身份证等特殊类型，触发反洗钱标志。  
   - 手机号需通过短信验证码验证，同一手机号关联多个保单时系统提示合并客户ID。

2. 产品选择与计划书  
   - 可选择在售产品，系统根据监管规则已内置条款、费率表、免体检额度，禁止手动修改费率。  
   - 计划书生成后若有‘分红/万能’演示，必须勾选“已阅读产品说明书及利益演示”复选框，且演示利率需严格使用监管规定的低/中/高三档。

3. 在线投保与风险提示  
   - 健康告知逐条展示，强制客户阅读并勾选“是/否”，若存在异常告知，系统自动标记为“人工核保件”。  
   - 长险产品自动弹出“投保提示书”，需客户电子签名，未签名拦截提交。  
   - 双录关联：满足双录要求的保单，系统强制进入“双录任务”模块，未关联合格双录音视频文件，无法生成投保单单号。

4. 反洗钱及受益人识别  
   - 单笔趸交保费≥20万元或投保人/受益人为外国政要等，系统弹出“客户身份强化识别问卷”，收集资金来源、职业背景，自动生成《反洗钱客户风险等级评估表》。  
   - 受益人未指定或为“法定”时，需在备注栏说明，否则无法通过核心校验。

5. 核保流程展示  
   - 自动核保：标准体且累计风险保额<100万，系统秒级给出“标准承保”结论并生成保单号。  
   - 人工核保：显示为待办任务，核保师可在“核保工作台”查看完整的投保单、体检报告（PDF）、病史材料，选择下发“体检函/生调函”或直接给出“加费/除外/拒保”结论。所有操作留痕，核保日志不可删除。  

 三、双录与可视化质检（销售合规核心）
对应员工手册“双录规范”及“严禁销售误导”。

- 双录视频上传：代理人通过APP端离线双录后，视频自动同步至系统，文件命名格式为`机构代码_保单号_录制时间`。  
- 智能质检：系统利用语音识别将对话转写为文字，自动校验是否包含规定话术（身份介绍、产品类型、犹豫期、退保损失），对缺失关键词标记“疑似违规”。人工质检员可从质检池抽取视频复核，录入“合格/整改”，并将结果推送到代理人待办。  
- 双录锁定：合格的双录文件与保单绑定，若保单在犹豫期内撤单或失效，双录文件于保单终止后按监管要求保存10年。

 四、理赔服务操作
对应员工手册第十一章。

1. 报案创建  
   - 客服接到955电话后，在“理赔-报案受理”界面输入报案人、出险人信息，系统自动匹配其在投保人名下的有效保单，显示险种及责任条款摘要。  
   - 小额医疗险案件可直接由客户通过官微自助报案，材料上传OCR识别发票、病历。

2. 审核与理算  
   - 理赔岗核对申请材料，标记缺失项可一键生成《补充材料通知书》短信链接发给客户。  
   - 进入理算环节，选择对应保单责任（如住院医疗、重疾），系统根据条款公式自动计算赔付金额，结果允许人工修正但需输入修改原因。  
   - 对于5000元以上非调查件，系统强制双人复核签字。

3. 调查与拒赔合议  
   - 需调查案件可创建调查任务派发给公估公司或内部查勘员，任务有超时预警（48小时更新）。  
   - 拒赔结论必须提交总分公司“理赔合议组”，在系统内完整填写《拒赔合议记录》，引用具体的条款编号及理由，生成《拒赔通知书》电子版，经法务会签后方可发出。

 五、客户信息保护与数据安全操作
严格遵循员工手册第十二章。

- 数据脱敏展示：用户查询客户列表时，证件号码中段以``遮盖﹔理赔病历摘要中的姓名显示为`张`。只有点击“查看完整信息”并经过二次身份验证（人脸或短信）后，才可展示明文，且该查看行为被审计日志记录。  
- 信息导出控制：任何含客户手机号、证件号的列表导出，必须申请数据导出权限，批处理后以加密压缩包形式发送至指定邮箱，密码通过短信下发，且文件7天后自动从服务器删除。  
- 用户超时锁定：系统无操作15分钟自动退出登录。

 六、其他常用功能关键操作
- 佣金计算：系统每月1日根据上月承保保单、续期回收、退保扣减等自动生成佣金报表，代理人可在代理门户核对并线上确认。
- 监管报表：营销员可在“报表中心”获取1314率、继续率等，支持按机构、月份生成。
- 投诉处理流转：接到监管转办投诉单后，合规岗在系统登记，转派至对应渠道主管，设定处理时限倒计时，处理报告及客户确认书需作为附件上传，逾期系统自动向分公司负责人发出督办通知。

 下篇：二次开发指导

 一、系统技术架构概览
ACIP采用主流微服务架构，基于Spring Cloud Alibaba技术栈构建。

- 前端：Vue 3 + Element Plus，移动端使用uni-app打包为代理人App。
- 后端微服务拆分：
  - `acip-product`：产品定义、费率表、条款管理
  - `acip-policy`：投保、核保、保全、续期核心保单生命周期
  - `acip-claim`：理赔报案、理算、支付网关对接
  - `acip-risk`：反洗钱、风控规则、双录质检引擎
  - `acip-agent`：代理人管理、佣金计算、组织发展
  - `acip-customer`：客户主数据、实名认证、360视图
  - `acip-gateway`：API网关，负责鉴权、限流、日志
- 中间件与存储：
  - 数据库：PostgreSQL 14（核心交易），Redis（缓存、分布式锁），Elasticsearch（客户搜索、日志检索）
  - 消息队列：RabbitMQ（异步处理如佣金结算、双录转码、状态机流转）
  - 对象存储：MinIO（双录音视频文件、影像资料）
- 部署方式：Kubernetes集群，基于GitLab CI/Jenkins构建CI/CD流水线。
- 安全组件：Spring Security + OAuth2.0，采用JWT令牌。

 二、开发环境搭建指南
1. 前置软件  
   - JDK 11+，Maven 3.8+，Node.js 16+，Docker Desktop。
   - IDE推荐IntelliJ IDEA（装Lombok、MyBatisX插件）及VS Code（前端）。
2. 代码获取及构建  
   - GitLab仓库：`git clone git@gitlab.encheng-life.com:acip/acip-backend.git`  
   - 本地启动：在各服务`resources`下修改注册中心地址为本地Nacos `localhost:8848`，使用`docker-compose`启动依赖中间件（Nacos, Redis, RabbitMQ, PostgreSQL）。运行`mvn clean install -DskipTests`，然后在IDE启动每个微服务的`Application`类。
3. 本地前端调试  
   - 进入`acip-web`目录，`npm install`后`npm run serve`，代理接口到网关本地端口。确保能登录并展示页面。

 三、代码规范与分支管理
- 分支模型：`main`（生产发布），`develop`（集成测试），`feature/xxx`（特性开发），`hotfix/xxx`。向`develop`及`main`合并必须提交Merge Request，经过至少一名核心开发Code Review并通过流水线所有阶段。
- Java规范：遵循阿里巴巴Java开发手册，使用Checkstyle和PMD插件强制检查。统一响应实体必须使用`com.encheng.common.Result<T>`包含`code, message, data`。API接口必须添加`@ApiOperation`并标注权限码。
- 前端规范：遵循ESLint + Prettier配置。组件名使用PascalCase，目录结构按业务模块划分。API请求统一封装在`@/api`，使用拦截器注入 token。
- 日志规范：敏感数据不输出到日志；使用`logback`，参数占位符替代拼接；全局异常处理记录堆栈并输出traceId。

 四、核心业务模块开发指南
 1. 新增保险产品
在`acip-product`服务中，产品配置通过“产品工厂”实现。开发人员需要：  
- 在数据库`t_product_define`中新增产品记录，`t_product_liability`定义责任代码、给付算法公式的Java类全限定名。  
- 如果给付算法特殊，需要编写一个实现`CalculationHandler`接口的类，并在Spring容器注册。  
- 费率表支持CSV导入，批量插入`t_rate_table`，注意必须加密存储再解密使用。前端计划书渲染会调用`/product/premium/calc`接口动态计算。

 2. 新理赔理算公式
如果是按比例给付或固定额，配置`t_claim_formula`表，定义公式类型`EXPRESSION`，格式如`amount  0.8`。若为复杂模型，需新增`ClaimCalculator`实现，注入上下文中获取发票金额、免赔额等，通过决策表模式配置化。每个新公式必须编写单元测试验证各种边界情况。

 3. 集成外部服务
- 如新增人脸识别供应商，遵循SPI扩展机制：创建一个`FaceRecognitionService`接口，实现类上加`@ConditionalOnProperty`指定供应商，配置切换即可。所有调用外部的服务必须包含熔断降级（Sentinel）和重试机制，且日志记录请求响应耗时。

 五、API开发与安全规范
- 接口设计：遵循RESTful，资源路径如`/api/v1/policies/{policyId}`。请求体使用JSON，DTO字段添加`@Valid`校验。时间格式统一用`yyyy-MM-dd HH:mm:ss`字符串。
- 接口文档：Swagger3自动生成，务必编写清晰的接口说明和示例。对外接口修改后连同更新API文档。
- 权限控制：每个Controller方法添加`@PreAuthorize("hasAuthority('POLICY_READ')")`，权限字符串由统一权限平台定义。任何接口必须先校验登录态和权限，再执行业务逻辑。严禁通过隐藏URL或仅前端控制来实现权限。
- 防越权：涉及保单、理赔等数据操作，必须校验该数据是否属于当前用户机构或数据权限范围。系统提供AOP切面`@CheckPolicyOwner`，在方法上使用，自动截取policyId并验证归属。

 六、数据库与数据处理规范
- 变更管理：使用Flyway进行数据库版本管理，文件命名`V1.0.0__description.sql`。所有DDL、DML需在代码合并时一并提交。严禁直接在生产库手动修改。
- 敏感数据加密：手机号、证件号、银行卡号等字段在数据库中使用AES-256加密存储，应用层使用自定义TypeHandler透明加解密。密钥存储在Vault中，禁止硬编码。
- 查询性能：关键查询必须走索引，禁止`SELECT `。多表关联复杂报表走Elasticsearch或只读备库。

 七、测试要求
- 单元测试：核心业务逻辑覆盖率至少70%，使用JUnit5 + Mockito。理赔计算、反洗钱规则等必须有数据驱动测试用例。
- 集成测试：在每个微服务中配置`@SpringBootTest`测试，模拟完整流程：投保->核保->双录->支付->承保。测试数据库使用H2或Testcontainers启动实际PostgreSQL。
- 安全测试：合入前运行OWASP Dependency Check扫描依赖库；渗透测试团队会定期扫描常见漏洞（SQL注入、XSS、越权）。开发自查防止将用户输入直接拼入SQL。

 八、版本发布与运维
- CI/CD：提交到`develop`自动触发构建、单元测试、代码扫描。合并至`main`后，经人工审批在Jenkins打包Docker镜像推送至Harbor，随后通过ArgoCD同步K8s配置实现灰度发布。先更新1个Pod观测日志无异常，再全量更新。
- 日志与监控：日志标准输出被Filebeat收集至ELK；指标通过Prometheus + Grafana监控JVM、QPS、接口错误率。报警规则设定为：接口5分钟内错误数>10条则触发钉钉群通知。
- 紧急版本回滚：保留最近3个版本的镜像，通过Kubectl rollout undo一键回滚。

 九、安全开发红线（一票否决）
- 严禁在前端代码或JS中硬编码后台接口地址、内部令牌、加密盐。
- 严禁直接在SQL中使用`${}`拼接用户输入（MyBatis中必须用`{}`）。
- 所有涉及资金变动（退费、理赔支付）的接口，必须进行幂等性处理（基于业务单号），并记录操作者、IP及时间戳到审计表`t_audit_trail`。
- 任何下载客户数据的接口，强制进行数据集数量限制（单次最多500条），超出则必须走异步文件生成流程。

 附录：常见问题及处理（开发侧）
   Q：本地启动报Nacos连接拒绝？  
    A：确认docker-compose启动了nacos，且bootstrap.yml中`spring.cloud.nacos.discovery.server-addr=127.0.0.1:8848`。
   Q：Swagger文档上如何测试需要鉴权的接口？  
    A：调用/auth/login接口获取token，点击Swagger右上角Authorize按钮，填入`Bearer {token}`。

（操作侧）  
   Q：投保单提交提示“预核保未通过”  
    A：请查看核保结果详情，大概率是健康告知或职业类别触发了拒保体规则，需转人工核保或更换险种。
   Q：双录视频一直显示质检中  
    A：视频时长较长时，ASR转写和AI分析需要15~30分钟。若超过2小时仍无结果，可联系IT服务台重启质检任务。
